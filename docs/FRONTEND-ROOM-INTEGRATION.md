# Frontend room integration contract

## Current Individual milestone and AI benchmark

The accepted 6 November scope completes Individual remote games first. Remote Team selection is disabled and new Team settings/starts are rejected by the authority; existing Team code/types and explicitly deferred coverage remain for a later plan. Older Team descriptions below are historical design context, not this milestone's acceptance gate.

RoomSnapshot.aiBenchmark contains nullable totalPoints and scoredRounds/solvedRounds/completedRounds. RoomGame.result.aiBenchmark contains scoringVersion `ai-benchmark-v1`, status `solved`/`unsolved`/`unavailable`, nullable points/elapsedMs and optional reason. An eligible zero is scored; unavailable is null and excluded from scored coverage. Missing older fields project unavailable/null/zero scored and solved rounds while preserving the known completed prompt count, never an incorrect inference. The engine emits normalized values and commits AI totals with the same atomic round result as humans.

Render authoritative AI round status/points in recap and a separate match total/coverage beside final human standings. Do not insert AI into human deltas or winner selection. Keep human AI modifiers zero. The production provider remains unavailable; positive AI data is confined to labelled test/review/local-demo fixtures. Components still use RoomClient; no client AI-answer/score command is added. The internal bound provider port leaves rendering, cadence, hosting and network transport to a later AI plan.

The room UI uses `RoomClient` with a local demo adapter by default. `NEXT_PUBLIC_ROOM_TRANSPORT=remote` opts into the HTTP/Socket.IO integration; `NEXT_PUBLIC_ROOM_API_URL` and `NEXT_PUBLIC_ROOM_SOCKET_URL` default to same origin. The real backend is now in `apps/api`; see its README for PostgreSQL setup. The local adapter and `/review` fixtures remain browser-local, with presentation-only scores. A remote production export uses the real backend and authoritative human-only scoring; no AI inference service is connected.

Bootstrap uses `POST /api/rooms` with `{profile}`, `POST /api/rooms/:code/join` with `{profile}`, and `GET /api/rooms/:code/resume` with a bearer resume token. Responses contain a `RoomSession`; the token must never be placed in a URL. The public snapshot must omit target words and unrevealed AI answers; drawer-only target data is separately delivered in private state. The active tab keeps its resume credential in session storage. The local demo also stores room snapshots and per-viewer credentials in IndexedDB; these are browser-local demo data, not secure account credentials. Closing a local room removes its room and associated credential records atomically.

The socket is created with `autoConnect: false` only after successful bootstrap. Commands are `room:settings`, `room:move`, `room:select-team`, `room:start`, `room:leave`, `room:chat`, `room:guess`, `room:drawing`, `room:resync`, `room:choose-prompt`, `room:retry-interrupted`, and `room:return-to-lobby`. A command envelope carries requestId, expectedRevision, generation and payload; server acknowledgements return `{ok, code?, message?}`. These names and payloads are implemented by the NestJS gateway. After an ambiguous timeout, a retry with the same command and payload retains the entire original envelope and request ID; a definitive acknowledgement clears it. The server must deduplicate request IDs, reject stale revisions/generations and send authorized data only.

`room:event` carries typed snapshot, connection, drawing, acknowledgement or gameplay events. Gameplay presentation changes must arrive in authorized snapshots with the required fields; generic gameplay extension events do not replace those snapshots. Ignore stale snapshots. Drawing submissions include the active canvas generation. A drawing event identifies canvas and generation, includes its canonical sequence, and marks `reset` for complete replay or incremental operations otherwise. `caughtUp` is true only once the replay reaches the current stream boundary. The UI must await hydration before enabling drawer input. On reconnect request a complete resync. For an interrupted remote stroke, the backend must define and deliver an authoritative closure; clients do not invent remote operations. The local demo closes an interrupted persisted stroke deterministically before replay.

Settings enforce individual default, six seats and six prompt rounds; teams are explicit. Local examples do not establish hosting capacity, AI behavior, score calculation, or reliable real-time networking. Scoring semantics are governed by `BACKEND-SCORING-PLAN.md`, not older preview values.

Local room mutations compare the persisted revision and write the room and viewer credential in one IndexedDB transaction. A stale tab receives a retryable error and must restore before retrying; no live cross-tab broadcast is provided.

## Lossless drawing-sync follow-up — 10 November 2026

Drawing remains a reliable, server-ordered operation stream, not bitmap streaming or AI input streaming. The browser still persists an immutable envelope before emission and retains accepted data until its contiguous durable watermark. The network window remains bounded at 16 outstanding submissions. No scoring, privacy, Team, inference cadence or database schema rule changes.

- **Bounded event-driven sender:** stroke starts, ends and edit commands flush immediately in order. Movement keeps the prior flush deadline, with a default maximum wait of 33 ms; an expired deadline sends new input promptly rather than adding a new full interval. Empty buffers produce no heartbeat. Default canonical payload limits are 64 KiB UTF-8, 128 operations and 1,024 total points, below server batch limits. Input and the actual destination header are validated before changing pending state or consuming a sequence number, including batch-number digit growth.
- **Exact input:** `MAX_STROKE_APPEND_POINTS` retains the server's 512-point per-append limit. Large browser-coalesced samples are chunked before assigning operation IDs, without rounding or dropping points. Already captured, persisted or transmitted operations are never split, renumbered or normalized for retry.
- **Canonical wire payload:** `DrawingPayload` carries batch/stream/room/canvas/generation identity, client sequence and operations. `DrawingBatch` retains local diagnostic fields for review/logging; `byteCount` is the exact UTF-8 size of the canonical payload, excluding diagnostics and the outer Socket.IO command envelope. Only new submissions omit diagnostics. Stored legacy envelopes keep their original complete payload, IDs and revision on retry; the server continues to accept them.
- **Grouped IndexedDB persistence:** up to 64 concurrently queued puts share a transaction, with no additional batching timer. Each caller settles only on commit or failure of its transaction. Reads and deletes flush earlier queued puts and share a storage-order chain, preserving metadata updates, pruning and expiry. Grouping does not combine envelope identities or skip any record.
- **Low-latency receiver coalescing:** an idle burst shares a microtask and starts promptly; following arrivals share the trailing display-frame pass. A 50 ms fallback timer schedules progress when frames are unavailable, subject to browser timer throttling. Hydration is an ordered reset barrier, and promises resolve after actual application, not receipt. Already seen local echoes still bypass replay while a pointer is held.
- **Bounded recovery:** the receiver retains at most 512 pending callers and 40,002 operation entries, allowing an active legal prefix plus a replacement reset. A reset itself is limited to 20,001 operations, including a canonical server closing operation. Overflow or replay failure rejects affected callers and requires an authoritative reset; incremental tails cannot report success after a failed prefix. The room invalidates stale replay callbacks, marks `caughtUp` false, and requests recovery without a retry storm. A failed reset is reported rather than silently skipping geometry. Disposal and invalidated scheduled work cannot start a late replay; a stale in-flight result cannot invalidate its replacement reset.

These are local implementation details, not a deployment or public-network latency claim. The [frontend validation report](FRONTEND-VALIDATION.md) records the measured candidate rejection, final checks and limits. Room metadata persistence now excludes drawing geometry before deep cloning; see [backend validation](BACKEND-VALIDATION.md).

## Drawing and round-flow responsiveness — 9 November 2026

Drawing transport retains the 33 ms batching target and persistence-before-send, with up to 16 batches in flight. IndexedDB version 2 caches its connection, preserves version 1 records and adds a player/room index. Queue counts use envelope metadata rather than repeated full database scans. Durable cleanup is single-flight and coalesced over 200 ms; accepted but undurable envelopes remain retained, including when their ACK arrives after the durable watermark. Expiry invalidates outstanding writes before deleting the old session's outbox, so a late ACK cannot resurrect a deleted envelope. Concurrent resync callers share one request. Timeout messages identify the command without including its payload or credential; ambiguous retries keep the entire original envelope.

`RoomGame.closing?: boolean` is authoritative and optional for compatibility. Closing makes the drawing/guess/tool controls read-only until the committed result arrives. Guess submission claims a synchronous pending token and shows “Checking your guess…” without fabricating correctness. A pending guess cannot submit twice; its completion cannot erase a subsequently edited draft or affect a different canvas/generation/session. Correct feedback remains generic for unsolved viewers. Saving and committed recap are distinct states. Recap uses the existing eight-second deadline with truthful next-drawer, waiting and final-standings labels; entry motion is 160 ms and disabled under reduced motion.

Already-applied local echoes do not schedule a replay/busy cycle while a stroke is held. Real resets, unseen operations, pending replay and fill work keep the existing replay path and synchronization barriers. Viewer-only canvas status changes do not rerender the entire room, and unchanged drawer status retains its identity. The canvas remains mounted through ordinary phase transitions.

These changes do not alter scoring, answer privacy, Team availability or AI provider behavior. See the dated validation reports for actual checks and limits; local fixes are not a deployment claim.

## Results, chat and prompt corrections — 7 November 2026

Presentation uses existing authoritative winners/standings, result deltas/components, next drawer and deadlines. Human scoring remains `human-v1`; rank cards and relative bars do not add score or change tie order. Equal scores share ranks such as 1, 1, 3. AI remains outside the human ranking with distinct null/unavailable and eligible-zero states.

The existing `ChatMessage.kind === "correct"` drives green, labelled confirmations. The accepted answer text remains hidden from unsolved viewers. Chat following uses the latest message ID rather than array length so the bounded history continues to follow new arrivals. Only the chat container scrolls; page position and focus remain stable.

For fresh matches, the authority stores private optional `selectedPrompts` in Room JSON and excludes all selected targets from later three-word offers, including interrupted retries. Selection time, rather than result commit, consumes a word. Offered but unselected words remain available. New matches reset the set. Older rooms missing this field preserve legacy behavior; strict non-repetition starts with a fresh match.

The 348-word API-owned catalogue does not load model resources at runtime. No new browser command, public history field or SQL migration is required. Exhaustion reuses `startBlockers` and host-only `canReturnToLobby` for interrupted/committed results; it cannot authorize abandoning an uncommitted active drawing.

## Complete remote session

The shared source of truth is `packages/game-contracts/src`; the frontend's existing `src/contracts` paths re-export it. A room progresses through `lobby`, `choosing`, `drawing`, `result`, and `finished`, with `interrupted` for an unfinished generation recovered after restart. The configured rounds count is total prompts, not complete rotations.

`room:choose-prompt` accepts `{id}` from the selecting drawer, using private `promptOptions: {id,label}[]`. The default choice window is 15 seconds, followed by an automatic available option; drawing lasts 60 seconds and recap lasts 8 seconds. Those are server configuration values. `deadlineAt`, `serverTime` and optional pause metadata drive the display; a browser never decides a score or phase transition. Hints progress on the authoritative drawing clock. AI status is `unavailable`, and AI-related bonuses/reductions remain neutral.

`room:return-to-lobby` is host controlled. `canReturnToLobby` communicates the authorized capability for final standings, a voided interrupted match, or a committed result waiting for the required players. It does not authorize abandoning an uncommitted active drawing. `room:retry-interrupted` retries the same round and drawer with fresh word choices after the roster is ready. `finalStandings` and `winners` are server-supplied; the frontend only renders them.

`sync.sequence` identifies the accepted canvas prefix; `sync.durableSequence` identifies the contiguous prefix committed to PostgreSQL. A live acknowledgement is not a promise of crash durability. The browser persists drawing envelopes in IndexedDB before sending them, preserves the same request ID across ambiguous retries, and retains accepted envelopes until the matching durable watermark. Replays are ordered and hydrated without echo. Old-generation records are never submitted to a fresh drawing; a discarded unconfirmed tail is reported rather than called saved. An interrupted remote stroke receives a server-owned closing operation. A disconnect pause also closes the accepted stroke canonically. Drawing submitted during that pause is definitively rejected (`drawing-paused`); the client retires the unsendable stream tail, shows a notice, restores the accepted canvas and rotates the stream before drawing continues. Ambiguous transport failures keep the original envelope and IDs; accepted but undurable entries still wait for the durable watermark.

`interruptedSketches` lists only sketches the viewer may read. `RoomClient.getInterruptedSketch(canvasId,generation)` uses the bearer-protected `GET /api/rooms/:code/interrupted/:canvasId/:generation`; the archive viewer uses a separate read-only canvas so it cannot replace live play. The latest committed interrupted prefix remains discoverable after retry.

Socket membership is authenticated before the server assigns room/player/team channels. Per-viewer snapshots and drawing delivery preserve private prompts and optional team canvases. One application session has one active socket lease; a replacement tab cannot leave the new connection marked offline when its old socket disconnects.

## Retained Team design — deferred

The earlier approved Team design uses one shared target: the selecting team rotates each prompt round, and its drawer chooses from three private words. All team drawers then privately receive the chosen target. Each team has its own canvas and first-human-solve closure; only progress is shared across teams. Individual remains the room default.
