Latest review direction

Separate text and number evidence

The Referee produces two independent presence scores. Text uses “Possible written clue detected.” Numbers receive a separate advisory. Thresholds and persistent observations filter the messages, and players decide whether writing is incidental or a prohibited clue.

This review direction supersedes the interim merged writing target. Advisory events carry zero score effects.

Text

Letters, initials and words

The text target is 1 whenever alphabetic writing is visible, including on objects. Its score qualifies for a possible-clue warning after its own threshold and persistence check.

Numbers

Digits and number strings

The number target is 1 whenever numeric writing is visible. Its score uses an independently tuned threshold and a separate numeric advisory policy.

Training targets and advisories after threshold and persistence qualify

Incidental object lettering and a written answer both have text target 1. The score supplies content evidence. Players supply the rule judgment. Arrows, circles and other icons alone trigger neither advisory.

The canvas seen by both models

One prepared image for each matching revision

Capture the current canvas, apply the Guesser's pinned foreground preprocessing once, then share the prepared tensor. Its shape is float32 [3,224,224], with the foreground fitted within 192 pixels and normalized using mean and standard deviation 0.5.

Training images

Guesser training renders Quick, Draw! prefixes. Referee training decodes ATYPICT PNGs. Both then use the same image transform. The training targets belong to their respective tasks.

Inference images

For a revision evaluated by both models, share its canonical raster, preprocessing version and prepared tensor. Each model has its own weights, head and evaluation schedule.

The existing CPU package uses Python 3.13. Its prepared tensors or reusable preprocessing core must be handed to the model runtimes consistently during implementation. Read the shared-input probe receipt.

Model plan

ViT-Tiny with two presence outputs

One shared image encoder

Fine-tune the same pretrained ViT-Tiny family as the Guesser. A two-logit head produces independent sigmoid scores for text and numbers.

Target order [text, number]

Use multi-label binary cross-entropy with known-label masks. Each channel can be positive on the same image.

Separate advisory policies

Text and numbers get independent validation thresholds and persistence counters. A high text score can qualify for “Possible written clue detected.” A high number score can qualify for a neutral numeric advisory.

Players decide whether writing is incidental or a prohibited clue. Arrows and circles alone trigger neither advisory.

Different from Quick, Draw!

The inspected release contains raster images and NumPy targets. No raw strokes, timestamps, prompt transcripts or session map appear in its inventories.

The paper describes collecting SVG sessions. That does not mean this ZIP supplies them or permits the Guesser's timestamp-prefix workflow.

How detection labels become classification labels

Reduce class columns across anchors

The multiclass target is a float32 array of 76,454 anchor rows × 9 values. Four values encode box regression; five values encode a one-hot class target.

Four regression values

dxdydwdh

These are encoded offsets. They are not pixel-coordinate boxes and are unnecessary for a presence classifier.

Five class values

bgtextnumbersymbolcircle

For each foreground column, take the maximum across rows. At least one positive anchor gives presence = 1.

Worked example: circle / 895

Its label array has 68 positive text anchors and 1 positive circle anchor. Reducing those columns gives [text 1, number 0, symbol 0, circle 1]. The Referee target uses the first two bits separately, giving [text 1, number 0].

The folder name would miss the writing. A five-way softmax would also force a mixed-content image into one category.

The text-only variant instead has 19,110 × 6 targets: four offsets followed by background and text. This is still a detector target. The text-only release has no number column, so it is excluded from the two-channel training plan.

A zero in either presence slot needs auditing before it becomes a trusted absence label for that channel.

Findings that change the plan

Audit the data before trusting a label

VISUALLY CHECKED

Writing with zero text labels

Text-only training sample 5906 visibly reads “flute”, yet every anchor is background. Its identical counterpart 4378 also has zero text anchors.

The probe cannot determine whether matching, annotation or export caused the miss.

SHA-256 VERIFIED

Cross-release leakage

Multiclass evaluation image 879 is byte-identical to text-only training image 2859.

Do not merge both releases' training/evaluation partitions. Use multiclass first; audit any future union.

115 cross-variant train/evaluation groups were CRC-size candidates. One pair was confirmed; 115 is not a verified duplicate count.

RELEASE LIMITATION

No original-session map

Exact pixel hashes help group identical images. They cannot establish that related snapshots or augmented versions belong to separate sessions.

No same-variant train/evaluation CRC-size match was found. This does not prove session independence.

Practical consequence: keep original anchor labels, add reviewed writing labels and exclusions, then group duplicates before splitting. Treat unreviewed all-background examples as weak supervision. Do not silently turn them into “clean drawing” ground truth.
A Guesser-style handoff

Six proposed data stages

The stage names mirror the Guesser workflow. These Referee scripts are a plan; they do not exist yet.

Acquire the chosen release

Pin the Zenodo record and choose multiclass explicitly. Sample mode reads bounded ranges; future training mode can acquire the two multiclass archives.

  • Keep exact source URLs, lengths, hashes and partial/full status.
  • Never let training initiate a dataset download.
  • Read nested ZIPs without expanding all dense arrays onto disk.
Output: source receipt + requested members

Pair and reduce detector targets

Match variant + archive + folder + sample number. Validate the schema and reduce text, number, symbol and circle columns across anchors, then retain text and number as independent target slots.

  • Use PNGs as compact pixels; compare representative image arrays.
  • Keep source bits separate from reviewed labels.
  • Hash pixels and flag missing, malformed or conflicting pairs.
Output: image records + encoded-presence proxies

Review writing labels

Inspect nominal negatives across provenance folders. Correct visible writing missed by anchor labels, including cases like sample 5906.

  • Review letters, words and digits anywhere.
  • Object writing is a positive content label. Players judge incidental versus prohibited use.
  • Use a small corrections file; preserve source evidence.
Output: contact sheets + corrections/exclusions

Group, split and export

Group exact and related images before an approximately 80/20 train/validation division of source training data. Keep source evaluation separate.

  • Do not merge the two variants by default.
  • Disclose opened multiclass evaluation images 4036, 2326 and 879.
  • State the missing session-map limitation and count unknown labels.
Output: PNGs + compact JSONL manifests

Load images and separate targets

A thin PyTorch Dataset adapter reads the manifest and PNG. DataLoader supplies standard batching, shuffling and workers.

  • Return the image, two targets and known-label mask separately.
  • Use reviewed negatives in the trusted prototype.
  • Exclude uncertain targets from supervised loss.
Output: one image + target + provenance

Transform exactly as inference will

Use the Guesser foreground transform, fit visible content within 192 pixels, pad to 224, repeat grayscale into RGB and normalize using mean/std 0.5.

  • Do not crop off writing or flip handwritten words.
  • Version background/fill handling and test live-game fixtures.
  • Return explicit uncertainty when preprocessing cannot handle input.
Output: float32 [3,224,224]
How to fine-tune it

Start small; test the value of adaptation

The starting checkpoint is timm's pretrained ViT-Tiny, about 5.7M parameters at 224 × 224. Use two independent presence outputs. Each model has its own weights and task head.

A · ENGINEERING BASELINE

Train the new head

Freeze the backbone. Up to five epochs, AdamW head LR 0.001. Establish whether pretrained features separate the audited examples.

B · PRIMARY CANDIDATE

Adapt the backbone

Three head warm-up epochs, then up to fifteen fine-tuning epochs. Start backbone LR at 0.00001 and head LR at 0.0001.

C · IF ERRORS JUSTIFY IT

Check shared input robustness

Evaluate the same prepared images on small text, digits, colors, fill and erasure. Version any shared preprocessing change for both tasks.

Sensitivity and persistent evidence

Tune each advisory on validation

Separate thresholds

Choose a high-precision operating point for text and another for numbers. Report each channel's precision, recall and false positives. Numbers can have a stricter advisory setting.

Use ATYPICT validation for content scores and labelled game replays for warning sensitivity and timing.

Persistent observations

A provisional start requires two consecutive fresh observations above that channel's threshold, at least one second apart with a maximum three-second gap. Observation IDs filter retransmissions.

Track text and numbers independently. Cooldown and lower exit thresholds prevent repeated warnings. Clear, restart and turn close retire incidents.
