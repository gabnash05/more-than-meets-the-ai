## Maintaining coverage

Use `terminal` for `git ls-files` and `git status --short --branch`, and `search_files` to inspect relevant untracked additions without indexing virtual environments, datasets, or caches. Every tracked `README.md`, every Markdown document under `docs/`, and each repository instruction file should have a literal path in this map. That baseline includes area READMEs such as `scripts/README.md` and `presentation/README.md`, so a new project area is routed when it lands rather than when someone remembers to widen the rule. Source directories are intentionally indexed as families rather than enumerating every implementation file. The checker at `.agents/skills/onboarding/scripts/check_repository_map.py` enforces that navigation baseline and detects missing literal paths; review prose relevance manually.

## Evidence and precedence

- `AGENTS.md` supplies repository-specific working constraints; follow it before general conventions.
- `README.md`, `CONTEXT.md`, and `SYSTEM-DESIGN.md` describe project intent, terminology, and system contracts. Task-specific plans refine their area.
- Current source code and tests show what is implemented in this checkout. A plan describes intended behavior; it does not prove implementation.
- Validation reports record checks at a particular time/environment. Re-run the relevant checks before claiming they pass now.
- If project documents conflict, use the latest explicit user decision where known. If that does not resolve the conflict, report it and ask rather than inferring from document dates or diagrams.
